# Research Student Portal — Upgrade Report

## 1. Overview

The portal was upgraded from the legacy (pre-2026) system to a configurable, policy-driven grading system implementing **DepEd Order No. 015 s. 2026** ("Guidelines on the Implementation of the K to 12 Curriculum for SY 2026-2027 and the MATATAG Curriculum for SY 2027-2028") and **DepEd Order No. 009 s. 2026** (school calendar for SY 2026-2027). All original features were preserved, security was hardened, and an administrator panel was added.

## 2. Grading Rules Implemented (verified against the official document)

| Feature | Implementation |
|---|---|
| KS4 SHS Core weights | WW 20% / PT 50% / EX 30% |
| Examinations internal split | ST1 30% / ST2 30% / TE 40% |
| MAPEH / TLE (old) | 20/60/20 (kept as a separate policy) |
| Transmutation | Official 40-row adjusted table (minimum 60.00, increments of 0.67/0.33), stored row-by-row and editable by the admin |
| Zero-based mode | No transmutation; from SY 2027-2028 (setting present) |
| Legacy mode | `legacy_linear` replicates the pre-2026 behavior for existing classes |
| Descriptors | English + Filipino bands (BG/BS/AP/D/N) editable by the admin |
| Terms | 3-term calendar per DO 009 s. 2026 (T1 2026-06-08 to 09-04, T2 09-07 to 12-11, T3 2027-01-04 to 04-08), plus the legacy single-term option |
| Missing scores | Excluded from computation (no zero penalty) for all DO 015 classes; legacy classes keep the old behavior |
| Publishing | Term grades are invisible to students until the teacher publishes them |

## 3. Architecture

- `db.php` — additive schema migrations + seeds (academic years, terms, 7 grading policies, 40-row transmutation, descriptors, calendar events, announcements, audit logs, settings, demo class).
- `grade_engine.php` — single source of truth for all computation: `class_policy()` (memoized per request), `compute_term_grade()` (PS/WS/IG/TG with exam split and weight normalization), `transmute_ig()` (4 modes), `class_terms()`, `class_is_published()`, `final_grade_from_terms()`, `target_requirements()`, `project_grade()`. It also owns the gradebook **write path**: `save_score_cells()` validates and persists edited cells, and `grade_row_payload()` / `class_item_averages()` / `class_category_averages()` / `class_grade_averages()` produce the payloads the browser patches in place. `grading_policy_groups()` returns the track-grouped policy catalogue for the picker.
- `db.php` — additive schema migrations + seeds **plus `migrate_grading_policies()`**, which installs the canonical policy catalogue (`grading_policy_catalog()`) on every load. Superseded policies are folded into the catalogue by renaming where a class still points at them, so existing grades are never re-parented.
- `grades_api.php` — JSON endpoint behind the live gradebook: teacher session + `X-CSRF-Token` header + class ownership, then validate → write → recompute → return. The grading rules are never re-implemented on the client.
- `includes/` — `actions.php` (POST dispatcher), `teacher.php`, `student.php`, `admin.php` (page modules).
- `dashboard.php` — slim router for teacher/student pages; `admin.php` — admin panel router.
- `login.php` / `register.php` / `logout.php` / `download.php` — hardened auth and file serving.

## 4. What Was Added

- **Teacher:** term-based gradebook with publish/unpublish, policy banner, ST1/ST2/TE item tags, per-term export/import (DO 015 ECR layout), "Excused" attendance, active-term setting, policy switching.
- **Spreadsheet gradebook entry:** all students × all activities in one editable grid, built to feel like Excel. The grid is the **first element on the page** — the category/weight editor moved into a collapsed *Activities & weights* panel beneath it, so entering scores never requires scrolling past setup. **Typing a score instantly recomputes that student's PS, IG, TG and descriptor plus the class-average row with no page reload** — the request goes to `grades_api.php`, which validates the cell (activity must belong to the class *and* term, student must be enrolled, value must be within 0…max), writes it, and returns the freshly computed row from the same `grade_engine.php` that renders the page. The grid autosaves on <kbd>Enter</kbd>/<kbd>Tab</kbd>/blur and after a 1.2 s typing pause; a "Save All Scores" full-form post remains as a fallback. Out-of-range values are rejected and flagged red instead of being silently dropped.
    - **Clipboard:** <kbd>Ctrl</kbd>+<kbd>V</kbd> pastes a column or block copied from Excel, filling down/across from the focused cell; <kbd>Ctrl</kbd>+<kbd>C</kbd> copies the selection out as tab-separated text that pastes straight into Excel. Pasted values outside the activity maximum are skipped and counted in the status line.
    - **Range operations:** <kbd>Shift</kbd>+arrows (or <kbd>Ctrl</kbd>+<kbd>A</kbd>) select a highlighted block; <kbd>Ctrl</kbd>+<kbd>D</kbd> fills it down from its first cell; <kbd>Delete</kbd> clears it (an empty score stays excluded rather than counting as zero); <kbd>Ctrl</kbd>+<kbd>Z</kbd> or the **Undo** button reverses the last bulk action. Every bulk action is a single undo entry and a single request.
    - **Orientation:** spreadsheet column letters (A, B, C …), row numbers, an outlined cell cursor with row/column header highlighting, collapsible category column groups persisted in the URL, and the student name column frozen left. IG/TG are deliberately *not* frozen right — a realistic gradebook is always wider than the viewport, so a right-frozen column permanently covers the last activity; *Collapse all* is the intended way to narrow it.
    - **In place:** a **+** button on each category banner opens that category's add-activity dialog without leaving the grid.
  - **Gradebook data integrity:** a unique index on `grade_scores (grade_item_id, student_id)` (with a one-off dedupe migration) guarantees one score per activity per student — without it a duplicated row is joined twice by the engine and silently inflates a category percentage.
- **Grading policy catalogue rebuilt to the current DepEd orders.** Policies are now declared once in `db.php` (`grading_policy_catalog()`) and installed by an idempotent `migrate_grading_policies()` that runs on every load, so a fresh install and an established database can never drift. Three defects were fixed:
  - **Dead-end templates.** *SHS Research Electives & Design Innovation*, *SHS Work Immersion* and *Legacy DO 8 s.2015* carried a name and description but **no component rows**, so selecting one produced a class whose gradebook said "Nothing to grade yet". Their components (40/60, 20/80, 25/50/25) are now installed. Research and Work Immersion also had no descriptors, so they returned "Not Graded"; they now carry the DO 015 bands.
  - **Missing SHS policies.** Added **Field Experience / Arts Apprenticeship / Creative Production** (15/70/15, administered as the Term Exam only — `ex_st1=0, ex_st2=0, ex_te=100`), **Arts, Sports, Health & Wellness** (20/60/20) and **TechPro Electives** (15/65/20), per DO 015 Table 10.
  - **Repealed descriptor bands.** All DO 015 policies now use **Advancing / Benchmarking / Connecting / Developing / Emerging** instead of the DO 8 s. 2015 labels; the DO 8 bands are retained only on the Legacy policy, which is historically correct. No grade *number* changed anywhere — only the descriptor label.
  - **Two-track structure.** DepEd Order No. 017, s. 2026 reduces Senior High School to **two tracks — Academic and Technical-Professional (TechPro)** with no strands, electives grouped in clusters, and Arts & Design / Sports electives reclassified under Academic. The picker is now grouped by track (`JHS`, `Academic`, `TechPro`, `Both Tracks`, `Other`) via a new `grading_policies.track` column, with the component weights shown inline (`… • 20/50/30`) and a hover tooltip carrying the full name and description. The select also got a **full-width row** on Create Class and Settings — it was a `col-md-6` inside a `col-md-7` card (~310 px) and truncated a 55-character policy name mid-word.
  - **Engine hardening.** A subject whose exam split assigns a group weight of 0 (Field Experience is Term-Exam-only) would assign weight 0 to a mis-tagged item, making the weighted total 0 and silently returning a Percentage Score of **0** regardless of the marks. Non-positive split values now fall back to equal weighting, so a mis-tagged item cannot zero a grade.
  - Superseded policy rows are folded into the catalogue by renaming where a class still points at them (preserving the id and therefore the grades), and retired rows that nothing references are deleted.
- **Removed the screenshot tool** — the floating Screenshot button, its `html2canvas` CDN dependency and the auto-capture queue (`screenshot.js`, `autoshot.js`) were deleted so the portal stays focused on grading; verified absent from every page.
- **Assignments:** per-assignment file policy (file required, accepted types, max size, late/cutoff), **Late** marking, "Download all (.zip)", and a "Not yet submitted" roster; submission files are private to the student + teacher (peer 403 verified).
- **Student:** term accordions with full PS/WS/IG/TG breakdown, target grade calculator, overall average + needs-attention alerts, published-grade gating.
- **Admin panel:** users (roles/status), academic years & terms, grading policies (weights, exam split, transmutation table, descriptors), school calendar, school-wide announcements, audit log, settings (school name, registration approval mode).
- **Security:** per-IP + per-email login throttling, POST-only CSRF-protected logout, 8-char password minimum, registration approval mode, account enable/disable, download access control, audit trail, `last_login`/`is_admin` session hardening.
- **Dark mode + UI polish:** a flash-free light/dark toggle (Bootstrap 5.3 `data-bs-theme`) with `localStorage` persistence and OS-preference default; theme-aware surfaces (cards, tables, inputs, navbar), a sticky branded navbar, button hover lift, and a smooth theme crossfade that respects `prefers-reduced-motion`.
